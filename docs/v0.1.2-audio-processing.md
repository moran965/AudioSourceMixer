# v0.1.2 音频处理与路由

## 普通 Windows 来源

普通 Core Audio session 只使用系统原生接口：

- 音量范围固定为 0–100%，写入 `ISimpleAudioVolume`。
- 静音写入 `ISimpleAudioVolume`；只有恰好两个可控制声道时才启用 `IChannelAudioVolume` 平衡。
- 不捕获目标进程 PCM，不创建附加播放副本，不启动 `ProcessBoostHost`。
- `ProcessLoopbackProbe` 仅用于开发研究，不编译进桌面运行时，也不进入 portable/installer。

旧配置按来源类型迁移：普通 Windows profile 的 `volume > 1` 截断为 1 并重写；明确标记为 Chrome/Edge 标签页的 profile 可保留到 2。

## 普通应用输出路由

`ApplicationRouteCoordinator` 以稳定可执行文件身份、PID 和进程启动时间标识本次应用实例。同一实例只有一个路由事务；每次请求递增 generation，取消旧验证，快速 A→B→A 最终只允许最新 generation 发布状态。同目标的在途或已完成请求幂等复用，不重复调用后端。

AudioPolicyConfig 对 Console、Multimedia、Communications 三个 role 事务写入并立即读回。策略读回成功后不会因为当前流未迁移而回滚：

- `SystemDefault`：应用持久路由已清空。
- `PendingStreamRestart`：策略正确，但没有活动流或活动流仍在旧端点；提示开始播放、暂停/恢复或重开应用。
- `Partial`：同应用只有一部分活动流到达目标。
- `Applied`：持久策略匹配，全部活动 sibling session 都在目标端点，并稳定至少 750 ms。
- `Disconnected`：目标设备不可用；保留已持久化策略并等待设备恢复。
- `Failed`：后端事务、读回或验证发生真正错误。

会话刷新、设备拓扑变化和跨端点产生的新 `AudioSourceId` 只更新观察状态，不因来源 ID 变化重复写入策略。

## 浏览器增强来源

用户点击扩展 action 后，真实 `tabCapture` stream 进入 offscreen 图：

`MediaStreamAudioSourceNode → GainNode (0–2) → StereoPannerNode → AnalyserNode → AudioContext.destination`

输出授权必须在可见页面由真实点击完成。service worker 以每标签页锁串行化命令，并以 `storage.session` 变更锁保存状态；offscreen 对同一图的 `setSinkId()` 串行化。每次结果携带 correlation ID，并读取实际 `context.sinkId`；缺少授权、deviceId 失效或 sink 不匹配时不会静默改为默认设备并声称成功。
