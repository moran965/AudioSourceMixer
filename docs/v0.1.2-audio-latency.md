# v0.1.2 延迟与质量记录

0–100% 普通 Windows 会话仅调用 Core Audio 原生音量/静音/声道接口，不捕获或重放 PCM，因此不引入应用级附加 audio buffer。普通来源不提供 >100% 增益。

输出路由是 AudioPolicyConfig 策略设置和 Core Audio session 观测，不在桌面程序内做 PCM 搬运。“已应用”需要全部 active sibling stream 在目标 endpoint 上稳定至少 750 ms；这是用于抵抗会话抖动的状态确认窗口，不是额外音频缓冲。没有 active stream 时保持 `PendingStreamRestart`，应用下次建流才能观测实际 endpoint。

浏览器路径的 Web Audio 缓冲由 Chromium 管理；每次 `setSinkId()` 记录调用耗时，但真实设备切换延迟仍需 Chrome/Edge 分别实测。
